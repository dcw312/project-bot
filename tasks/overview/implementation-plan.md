```python
class DiscordUser(models.Model):
    discord_id = models.CharField(max_length=64, unique=True)
    username = models.CharField(max_length=128)
    is_authorized = models.BooleanField(default=False)
    authorized_at = models.DateTimeField(null=True, blank=True)

    def __str__(self):
```

**`Project`**
- `creator` uses `on_delete=models.PROTECT` — prevent deleting a user who owns projects
- `creator` immutability enforced in the service layer, not the model

```python
class Project(models.Model):

    created_at = models.DateTimeField(auto_now_add=True)
```

**`ProjectMember`**
```python
class ProjectMember(models.Model):
    OWNER = 'owner'
    COLLABORATOR = 'collaborator'
    ROLE_CHOICES = [(OWNER, 'Owner'), (COLLABORATOR, 'Collaborator')]

    project = models.ForeignKey(Project, on_delete=models.CASCADE, related_name='members')
    user = models.ForeignKey(DiscordUser, on_delete=models.CASCADE, related_name='memberships')
    role = models.CharField(max_length=16, choices=ROLE_CHOICES)

    class Meta:
        unique_together = ('project', 'user')

    def __str__(self):
        return f"{self.user.username} — {self.project.name} ({self.role})"
```

**`Task`**
```python
class Task(models.Model):
    TODO = 'todo'
    DOING = 'doing'
    DONE = 'done'
    STATUS_CHOICES = [(TODO, 'Todo'), (DOING, 'Doing'), (DONE, 'Done')]

    HARD = 'hard'
    SOFT = 'soft'
    DEADLINE_CHOICES = [(HARD, 'Hard'), (SOFT, 'Soft')]

    project = models.ForeignKey(Project, on_delete=models.CASCADE, related_name='tasks')
    title = models.CharField(max_length=512)
    description = models.TextField(blank=True, null=True)
    status = models.CharField(max_length=8, choices=STATUS_CHOICES, default=TODO)
    priority = models.IntegerField(default=3)
    due_date = models.DateTimeField(null=True, blank=True)
    deadline_type = models.CharField(max_length=8, choices=DEADLINE_CHOICES, default=SOFT)
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        ordering = ['priority', 'created_at']

    def __str__(self):
        return f"[{self.status}] {self.title}"
```

## Step 5 — Ollama Integration Module

**Goal:** Encapsulate all Ollama communication in a single module. Includes startup validation, prompt loading, the chat call, and response parsing.

### Files to create or modify

- `bot/ollama_client.py`

### Key implementation details

**Module-level constants (read once on import):**
```python
OLLAMA_BASE_URL = os.environ.get('OLLAMA_BASE_URL', 'http://localhost:11434')
OLLAMA_MODEL = os.environ['OLLAMA_MODEL']   # fail fast if not set
PROMPT_DIR = Path(settings.BASE_DIR) / 'prompts' / OLLAMA_MODEL.split(':')[0]
SYSTEM_PROMPT_PATH = PROMPT_DIR / 'system.txt'
```

Note: `OLLAMA_MODEL` may be `lfm2:latest` — strip the tag when forming the prompt directory so the path resolves to `prompts/lfm2/`.

**`validate_ollama_startup()`** — called once at bot startup:
- `GET {OLLAMA_BASE_URL}/api/tags` — parse JSON, check `OLLAMA_MODEL` is in the `models` list
- If not found: raise `RuntimeError` with a clear message
- If `SYSTEM_PROMPT_PATH` does not exist: raise `FileNotFoundError`
- Load and cache `system.txt` content into module-level `_system_prompt`

**`build_messages(user_message, context_summary)`:**
```python
def build_messages(user_message: str, context_summary: str) -> list[dict]:
    system_content = _system_prompt + "\n\n## Current context\n" + context_summary
    return [
        {"role": "system", "content": system_content},
        {"role": "user", "content": user_message},
    ]
```

**`chat(user_message, context_summary)`:**
- `POST {OLLAMA_BASE_URL}/api/chat` with `{"model": OLLAMA_MODEL, "messages": ..., "stream": False}`
- Timeout: 120 seconds
- Returns `(parsed_response_dict, elapsed_ms)` tuple
- On `requests.RequestException`: raise `OllamaUnavailableError`
- Raw LLM content is in `response["message"]["content"]`

**`parse_llm_response(raw_content: str)`:**
- Strip markdown code fences if present (e.g. ` ```json ... ``` `)
- `json.loads(raw_content)` — on `JSONDecodeError` raise `LLMResponseParseError`
- Validate required keys: `action`, `data`, `message`
- Validate `action` is one of the five supported values
- Return the parsed dict

**Custom exceptions:**
- `OllamaUnavailableError`
- `LLMResponseParseError`

**Ordering dependency:** Step 1 (settings/`BASE_DIR`) must exist. Step 7 (system prompt file) must exist before `validate_ollama_startup()` succeeds at runtime.

## Step 7 — System Prompt

**Goal:** Write the static system prompt file for the `lfm2` model.

### Files to create or modify

- `prompts/lfm2/system.txt`

### Full prompt content

```
You are a project and task planning assistant integrated with a Discord bot.

Your job is to help users manage their projects and tasks by interpreting their
messages and returning a structured JSON response.

## Rules

- Always respond with valid JSON. Do not include any text before or after the JSON object.
- Do not use Python function call syntax. Do not use XML tags. Do not use markdown code fences.
- Only use supported actions listed below.
- Never hallucinate project names or task IDs. Only reference projects and tasks that exist in the current context.
- Prefer small, actionable task titles.
- If the user's intent is conversational (no task/project action required), use the no_op action.

## Response format

Your response must be a single JSON object with this exact structure:

{
  "action": "<action_name>",
  "data": { ... },
  "message": "<natural language reply to show the user>"
}

## Supported actions

### create_project
Create a new project. Optionally include starter tasks.
data: { "name": "string", "description": "string (optional)", "tasks": [ { "title": "string" } ] }

### add_task
Add a single task to an existing project.
data: { "project_name": "string", "title": "string", "description": "string (optional)", "priority": 1-5 (optional, default 3), "due_date": "ISO8601 datetime (optional)", "deadline_type": "hard or soft (optional, default soft)" }

### update_task
Update one or more fields of an existing task.
data: { "task_id": integer, "fields": { "title": "string (optional)", "status": "todo|doing|done (optional)", "priority": 1-5 (optional)", "due_date": "ISO8601 (optional)", "deadline_type": "hard|soft (optional)" } }

### list_tasks
List the user's tasks, optionally filtered by project.
data: { "project_name": "string (optional)" }

### no_op
No database action required. Reply conversationally.
data: {}

## Current context

(The current user's projects and open tasks will be appended here at runtime.)
```

**Ordering dependency:** No code dependency, but must exist before `validate_ollama_startup()` succeeds at runtime.

## Step 8 — Bot Management Command

**Goal:** Implement the Discord bot as a Django management command.

### Files to create or modify

- `bot/management/__init__.py`
- `bot/management/commands/__init__.py`
- `bot/management/commands/run_bot.py`

### Key implementation details

**Top-level structure:**
```python
class Command(BaseCommand):
    help = 'Run the Discord bot'

    def handle(self, *args, **options):
        validate_ollama_startup()   # fail fast before connecting to Discord
        token = os.environ['DISCORD_BOT_TOKEN']
        client = build_client()
        client.run(token)
```

**`build_client()`** — constructs `discord.Client` with intents and registers a `CommandTree`.

**`on_ready`:** sync slash command tree, print startup confirmation.

**`on_message` routing:**
1. Skip messages from bots
2. Skip messages that start with a mention of a user who is not the bot
3. Run `services.process_message` in a thread executor (it's synchronous/ORM)
4. While waiting, poll every 0.5s — if elapsed exceeds `LLM_THINKING_THRESHOLD`, send "Thinking..."
5. On response: edit the "Thinking..." message if it was sent, otherwise send a new message
6. If `needs_move_button=True`: attach a Discord UI View with a "Move to another project" button
7. If `response_text is None` (unauthorized): delete thinking message if sent, do nothing else

**`message_starts_with_other_mention(message, bot_user)`** helper:
- Detect leading `<@...>` or `<@!...>` tokens
- Return `True` only if the mentioned user is not the bot itself

**Slash commands:**
- `/authorize @user` — check `is_admin()`, call `services.authorize_user()`, reply ephemeral
- `/add_collaborator @user <project>` — call `services.add_collaborator()`, handle `PermissionError`/`ValueError`
- `/link_project <project>` — call `services.link_channel_to_project()`, handle errors

**"Move to another project" button:**
- `discord.ui.View` with a single `discord.ui.Button`
- On click: send ephemeral message listing user's other projects (full move logic is a future iteration)
- View timeout: 60 seconds

**Ordering dependency:** Steps 5 (ollama_client) and 6 (services) must be complete.

## Step 10 — Wiring and Startup Validation

**Goal:** Confirm where startup checks live and document the full boot sequence.

### Key implementation details

**`.env` loading:** `config/settings.py` calls `load_dotenv()` at import time. All management commands inherit this automatically.

**`run_bot` startup sequence:**
```
manage.py run_bot
  → Django loads settings → load_dotenv() fires
  → Command.handle()
      → validate_ollama_startup()
          → Check SYSTEM_PROMPT_PATH exists
          → GET /api/tags — confirm OLLAMA_MODEL is listed
          → Cache system prompt into _system_prompt
      → build_client()
      → client.run(DISCORD_BOT_TOKEN)
```

**What does NOT validate Ollama:**
- `runserver` — admin must work even if Ollama is down
- `migrate` — DB-only operation
- `bot/apps.py` `ready()` — runs on every Django startup including migrations; keep it empty

**Environment variable failure modes:**

| Variable | Behavior if missing |
|---|---|
| `DJANGO_SECRET_KEY` | `ImproperlyConfigured` at settings load |
| `DISCORD_BOT_TOKEN` | `KeyError` in `handle()` before bot starts |
| `OLLAMA_MODEL` | `KeyError` in `ollama_client.py` at import |
| `DJANGO_ADMIN_PASSWORD` | `KeyError` only in `create_superuser.py` |
| `DISCORD_ADMIN_IDS` | `get_admin_ids()` returns `[]`; no one can authorize |
| `LLM_THINKING_THRESHOLD` | Defaults to `5` |
| `DATABASE_PATH` | Defaults to `data/db.sqlite3` |
